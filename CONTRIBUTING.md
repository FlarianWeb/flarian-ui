## Новый компонент: сиквенс
```bash
pnpm scaffold <Group>/<Name>   # например: pnpm scaffold Display/Badge
```
Скрипт создаёт файлы и регистрирует компонент в баррелях. Дальше по порядку:
1. **`types.ts`** 
	- Пропсы, оси (const-объект + union).
	- `ButtonSlot`-подобный список слотов.
	- `<name>InstanceVars` (публичные инстанс-переменные).
2. **`config/components/<name>/`**
	- `types.ts` (props + tokens) и `defaults.ts` (значения).
	- Дефолты токенов здесь - источник правды.
3. **`<Name>.module.pcss`** 
	- Стили. Каждый конфиг-токен читается как `var(--ui-<name>-<путь>, <дефолт из defaults.ts>)`.
	- Оси - классами (`.size-md`).
	- Транспортная «ось → .root» - приватные `--_*`.
4. **`<Name>.vue`** 
	- `defineProps`-деструктура с дефолтами из `getConfig().components.<name>.props.*`.
	- Карта классов `cx` типа `UiComponentClasses<'<kebab>', <Name>Slot>` - тип требует стабильный `ui-<kebab>` первым в root (в него плагин эмитит конфиг-токены).
5. **`<Name>.contract.spec.ts`** 
	- при наличии tokens, по образцу `Button.contract.spec.ts`: «TS-дефолты + инстанс-вары = всё, что читает pcss», включая равенство значений.
6. **`<Name>.spec.ts`**
	- поведение: рендер, оси, a11y, события.
	- Мок runtime - из реального `defaultComponentConfig` (см. `Button.spec.ts`).
7. **`story/<Name>.story.vue`** 
	- playground с контролами из `getConfig()` + docs-блок (`<docs lang="md">`).
8. **ВАЖНО:**
	- Экспорт публичного API в `src/index.ts` (ручной шаг - осознанное решение, что торчит наружу).

## Конвенции стилей
- **Оси - классами**: 
	- Перечислимый проп (`size`, `radius`) → класс `.size-md`;
	- Инлайн-стили только для вычисляемых значений;
- **Три уровня переменных**:
	- Конфиг-токен `--ui-button-padding-y-md` (дефолт задаёт кит) → приватная `--_padding-y` (транспорт) → инстанс-вар `--ui-button-padding-y` (кит только читает, отсутствие = «работает ось»).
	- Осевые инстанс-вары **нельзя** эмитить конфигом - убьют ось.
- **Где резолвить `--_x`: `.local` vs свойство-потребитель**
	- Правило одно: `.local` объявлен в файле РАНЬШЕ `.size`/`.color`/`.variant`. У классов одинаковая специфичность → при равной специфичности побеждает тот, кто ниже по файлу. Если одну и ту же `--_x` объявить и в `.local`, и в `.size-*`, `.size-*` молча перезатрёт `.local` целиком - без ошибки, без предупреждения.
	- Токен **размерный** (есть `.size-*` вариант: `gapY`, `paddingX`, `fontSize`…) → bare-override пишется прямо в свойстве-потребителе: `gap: var(--ui-button-gap-y, var(--_gap-y));`. В `.local` эту переменную не трогать - `--_gap-y` объявляется только внутри `.size-*`.
	- Токен **скалярный** (без size-варианта: `fontFamily`, `fontWeight`…), используется **в одном месте** → тоже прямо в свойстве-потребителе, без `--_x` вообще. Обёртка через `.local` тут ничего не экономит, только лишний уровень непрямого обращения.
	- Токен **скалярный**, используется **в двух и более местах** (`hoverMix`/`activeMix` - до 4 вариантов × hover/active) → резолвить один раз в `.local`: `--_x: var(--ui-button-x, <дефолт>);`, дальше везде `var(--_x)`. Вот это и есть DRY, ради которого существует `.local`.
	- Итог: `.local` - только для переиспользования, никогда для «удобно смотреть рядом» или как единственная попытка проверить bare-override у размерного токена.
- **Hover/active**
	- Деривация `color-mix(in oklab, …)` с единой семантикой «сила сдвига» для всех вариантов (`hoverMix`/`activeMix`).
- **`@layer` руками не писать**
	- Оборачивается PostCSS-плагином.
- **Transition-классы**
	- из CSS-модуля явными пропами `<Transition>` (не глобальные имена).

## Конвенции кода
- Тесты: `*.spec.ts`, describe/it на русском, JSDoc-комментарии.
- `ref`/`computed`/`inject` - auto-import (unplugin-auto-import).
- JSDoc объясняет «почему», а не пересказывает код; неочевидные решения
  документируются в месте применения.
- Vue-plugin-инфраструктура не используется: runtime store - модульный
  singleton, состояние composables - per-app контейнер (`appState.ts`).

---

## A11y-контракт
- Интерактивный компонент в состоянии `loading` не получает нативный
  `disabled` (tab-order сохраняется) - `aria-busy` + `aria-disabled`.
- Кнопка без текста получает имя через fallthrough `aria-label`.
- Анимации уважают `[no-motion]` (глобальные правила генерирует
  `generateTokensCSS`).
